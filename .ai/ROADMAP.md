# Roadmap

다음 주요 작업 계획. 실행 전 논의로 확정된 설계만 기록(코드 변경 없음, 실행은 별도 세션).

## 탭 재구성 (dongorae 프론트)

Context: 기존 탭(대시보드/거래내역/투자/자산/보험/세금)이 서로 연관성이 부족하고 정의가 불명확함. 특히 "부동산"이 투자/자산 양쪽에 중복 존재, "관리" 서브탭이 3곳(투자/자산/보험)에 있어 각각 뭘 관리하는지 이름만으론 구분 불가. 세금 탭은 내용 없이 "준비 중" placeholder.

### 대분류 기준

- **자산** = 특정 시점의 보유 현황/평가액 (계좌, 부동산 스냅샷)
- **투자** = 매매 행위와 수익률/분석
- **보험** = 증권/청구/보장 내역
- **세금** = 예상세액 시뮬레이터 + 실제 납부 기록 (실제 신고·납부는 법무사를 통해 진행하므로 앱은 계산과 기록만 담당)
- **설정** = 기존 admin 전용 관리탭을 최상위 탭으로 승격. 가족·데이터관리·위험구역 등 앱 운영 설정 전담(admin 역할에게만 노출, 기존과 동일)
- **대시보드** = 위 4개(자산/투자/보험/세금)를 가로지르는 요약 진입점, 자체 서브탭 없음

### 확정된 탭 구조

**대시보드**
- 서브탭 없음. 순자산 총액, 최근 거래, 자산 배분 비중 등 요약만 표시.

**자산** (보유 현황/평가액)
- 계좌 — 예금/증권계좌 잔고 (조회 전용)
- 부동산 — 보유 부동산 시세평가, 대출/전세보증금 (조회 전용)
- 거래내역 — **모든 거래의 유일한 입력 창구.** 기존 통합 수동입력 폼(`app.js` `MOV_KINDS`: 환전/이체/입금/출금/이자/배당/수수료/세금/입출고/매수/매도)을 그대로 유지, cashbook·invest 카테고리 전부 여기서만 등록. 화면엔 전체 목록이 보이되 invest(매매) 건은 투자>주식에서 필터링해 다시 보여줌.
  - **행별 잔액 표시 개선**: 기존엔 계좌 하나를 선택했을 때만 그 계좌 기준 잔액 컬럼(원화/외화)이 보였는데, 계좌 선택 여부와 무관하게 **각 행의 나감 다리는 나감 계좌 자체 기준, 들어옴 다리는 들어옴 계좌 자체 기준**으로 잔액을 항상 표시하도록 변경. 컬럼명도 "원화잔액/외화잔액"(통화 고정) → "나감 후 잔액/들어옴 후 잔액"(해당 다리의 통화로 표시)으로. 이체(A→B)처럼 두 계좌가 섞여도 각자 자기 계좌 기준이라 헷갈리지 않음. 기존 `movements.running_cash(account_id)`(계좌 단위로 전체 이력을 훑어 {거래ID: 잔액} 맵 생성)를 그대로 재사용, `web.py:1164`에 이미 있는 계좌별 캐싱(`rc_cache`) 패턴 적용 — 화면에 등장하는 계좌 수만큼만 계산되므로 전체 거래 건수(수만 건)와 무관하게 비용이 낮음. "선택 계좌 잔액" 상단 요약 패널(계좌별 총 잔액)은 목적이 달라 그대로 유지.
- 관리 — 계좌/부동산 항목(계좌 자체, 부동산 자체) 등록·수정·삭제. 거래 입력과는 별개(거래는 거래내역에서만).

**투자** (매매 행위/수익률)
- 주식 — 보유종목 현황 + 매매내역. **입력 버튼 없음** — 자산>거래내역에 입력된 것 중 invest 카테고리(매수/매도)만 필터링해 보여주는 뷰. KIS 연동으로 보유종목 현재가만 갱신.
- 관심종목 — 아직 안 산 주식 워치리스트 (관심 등록, 목표가 메모)
- 관심매물 — 부동산 워치리스트. 기존 결정(DECISIONS.md 2026-07-12)의 "관심매물" 용어와 일치, 관심종목과 짝을 이루는 이름. 국토부 실거래가 자동 첨부 + 임장/수익률 시뮬레이션. 자산 탭의 "보유 부동산"과는 별개 데이터(미보유 매물).
- 분석 — 수익률·배당·추이·비중 + 미래 수익 시뮬레이션. 확장 후보(보류): 벤치마크(코스피/S&P500) 비교, 환율효과 분리, 세후 수익률.
- 관리 — 순수 설정 화면(리스트 조회 아님). 종목 매핑/정정(거래내역의 종목명↔티커 연결, 기존 `symbols.csv`/`instruments.py` 심볼 해석에 반영), 섹터·자산군 분류체계 설정.

**보험** (증권/청구/보장)
- 약관 — 관리에 등록된 상품별 보장내용(가입금액, 자기부담금, 면책조항 등) 열람. 청구 입력 시 보장 여부 참고용.
- 청구 — 사람(의료비/상해)뿐 아니라 대물/차량·배상책임까지 포괄. 등록 시 **청구 유형** 선택(의료비/상해 · 대물/차량 · 배상책임) → 유형별 필드 분기(의료: 병원·병명·진료비 / 대물: 사고일자·파손물·정비소·수리비·상대방정보 / 배상책임: 사고일자·피해내용·배상금·상대방정보). 기존 문서정리 흐름(스캔 import→검토대기→표준 파일명 정리)은 유형 무관 공통 재사용. **청구 상태**(접수/심사중/지급완료) + 실지급액 필드 신규 추가.
- 관리 — 등록된 보험 상품 관리 + **상품 종류 태깅**(실손의료/정액담보/자동차/화재/배상책임 등). 이 태깅이 청구 등록 시 유형 선택지를 좁히는 데 연결됨.

**세금** (예상세액 시뮬레이터 + 실제 기록)
- 해외주식 양도세 — 투자>주식의 매매내역 기반 자동 실현손익 집계 → 예상세액. 기본공제(250만원)·세율(22%) 적용.
- 부동산 양도세 — 자산 탭의 **보유** 부동산을 매도한다고 가정한 예상세액.
- 부동산 취득세 — 투자>관심매물(미보유)을 매수한다고 가정한 예상세액.
- 납부내역 — 위 항목들의 **실제 납부액**을 기록하는 공용 서브탭 (예상액과 비교 목적, 연도별/전체 흐름 확인).

**설정** (admin 전용, 기존 `#view-admin` 승격)
- 가족 — 기존 dongorae 관리탭의 "가족 관리" 카드(비로그인 가족 등록 + 로그인 사용자 승인/소유자 지정)를 그대로 이전. **신규: 가족 구성원별 "자산 집계 포함" 토글**(기본 ON). OFF 시 그 사람 소유(owner) 계좌/부동산/보유종목을 대시보드 순자산·자산 탭 목록·투자 탭 보유종목에서 제외(데이터 삭제 아님, 필터일 뿐 — 언제든 재포함 가능). 예: 자녀 계좌 끄고 본인+배우자만 보기.
  - auth-server의 별도 `/admin` 페이지(로그인 서버 쪽 가족관리 중복 UI)는 완전 제거하지 않고 **앱 접근 불가 시 대비한 비상용으로만 유지**. 관리탭 사용자박스의 "가족관리" 링크는 auth-server `/admin`이 아니라 앱 내부 설정>가족으로 변경.
- 데이터 관리 — 파일 업로드, 자동 적재(imports 폴더 스캔), 시세 갱신, 데이터 검증(대사), 데이터 내보내기 (기존 5개 카드 그대로 이전)
- 위험 구역 — 전체 초기화 (`resetLedger`, 기존 그대로)

### 데이터 의존 관계

- 자산>거래내역(원천, invest 카테고리) → 투자>주식(필터링된 뷰, 입력 없음) → 세금>해외주식 양도세(그 매매내역으로 손익 계산)
- 세금>부동산 양도세 ← 자산>부동산 (보유 정보: 취득가, 보유기간)
- 세금>부동산 취득세 ← 투자>관심매물 (미보유 매물)
- 투자>분석과 세금은 "실현손익" 데이터를 공유하되 관점이 다름: 분석=수익률 관점, 세금=과세 관점
- 설정>가족의 "자산 집계 포함" 토글 ← owner 소유 모델(기존 결정: 계좌=사람별 소유, owner 롤업) 기반 필터. 대시보드 순자산 스냅샷·자산 탭·투자 탭 전반에 영향.
